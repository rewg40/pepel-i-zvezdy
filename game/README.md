# Пепел и Звёзды — арена (Godot 4.3+)

Тестовая сцена: медик с мечом и три зомби на острове. Отдельная папка, чтобы не
смешивалась с исходными моделями (`остров/`, `зомби/`, `персонаж/`, `предмет/`).

## Как запустить

1. Установить Godot **4.3 или новее** (обычная версия, не .NET).
2. Открыть папку `game/` как проект (`Project → Import → game/project.godot`).
3. Дождаться импорта моделей (первый импорт `island.glb` ~27 МБ, может занять минуту).
4. **F5** — сцена `main.tscn` собирается кодом и сразу стартует.

| Клавиша | Действие |
|---|---|
| WASD | ходьба |

## Что реализовано

* **Карта** — `models/island.glb`: остров из репозитория, децимированный
  (террейн 500k треугольников, растительность лёгкая). Коллизия земли —
  `HeightMapShape3D` из `models/heightmap.png` (221×221, 1 м на клетку, участок
  220×220 м вокруг арены). Позиция арены выбрана автоматически по самому ровному
  сухому месту (`models/arena.json`).
* **Медик** — `models/medic.glb`: 6 частей, скин на 20 костей, анимации
  `Idle / Walk / Run / Attack / Hit / Death`. Меч — `models/sword.glb`,
  прицеплен к кости `Hand_R` через `BoneAttachment3D`.
* **Зомби ×3** — `models/zombie.glb`: те же 6 частей, анимации
  `Idle / Walk / WalkNoArms / Attack / Hit / Death / Crawl`.
* **Отрубание**:
  * тело 1000 HP, руки и ноги по 3 HP (удар мечом снимает 1 HP с конечности —
    то есть ровно 3 удара);
  * какая часть получила удар, определяется по расстоянию от точки попадания до
    кости конечности (рука/нога/голова), иначе урон идёт в тело;
  * отрубленная часть скрывается, на её месте включается кровавая «заглушка»
    (`*_Cap_*`), а копия конечности вылетает как `RigidBody3D` и остаётся лежать;
  * нет двух ног → состояние `crawl`: анимация `Crawl`, скорость 0.55 м/с,
    корпус у земли;
  * нет одной ноги → `limp` (медленная ходьба);
  * нет двух рук → анимация `WalkNoArms`; одна рука — обычная `Walk`
    (отсутствующая рука просто скрыта).
* **HUD** — прицел, подсказки и строка состояния каждого зомби
  (тело HP, сколько рук/ног, режим передвижения).

## Внешние клипы (Mixamo)

В `models/` лежат два файла с ретаргетнутыми клипами Mixamo:

| файл | клипы |
|---|---|
| `models/medic_clips.glb` | `MxIdle, MxWalk, MxRun, MxSlash, MxAttack, MxHit, MxDeath` |
| `models/zombie_clips.glb` | `MxWalk, MxRun, MxCrawl, MxAttack, MxHit, MxDeath, MxIdle` |

Они подмешиваются в `AnimationPlayer` при старте (`_merge_clips`), а выбор между
родными и внешними клипами делает `@export var clip_prefix` у `player.gd` и
`zombie.gd`: по умолчанию `"Mx"`, то есть игра играет именно клипы Mixamo, а если
поле очистить — вернутся родные. Файлов нет — игра работает как раньше.

Как пересобрать или добавить свои клипы (без Blender):

```bash
/tmp/venv/bin/python tools/retarget.py clips/*.fbx game/models/zombie.glb \
    game/models/zombie_clips.glb --prefix Mx --rename walking=Walk --rename crawling=Crawl
```

Подробности и ключи — в `tools/README.md`, раздел «Внешние анимации».

## Важно про GLB в git

`.gitignore` исключает `*.glb`, но для `game/models/*.glb` сделано исключение:
модели лежат в репозитории, чтобы проект открывался сразу. Если пересобирать их
скриптами из `tools/` (см. `tools/README.md`), не забудьте закоммитить результат.

## Что можно подкрутить

* `player.gd → sword_offset`, `sword_rotation_deg` — посадка меча в руке.
  Меч висит на кости кисти: `+Y` кости идёт от запястья к пальцам, поэтому
  клинок направлен вдоль `+Y` (поворот на 180° по X).
* `main.gd → MODEL_SCALE` (1.65) — рост персонажей в метрах.
* `zombie.gd → BODY_HP / LIMB_HP / LIMB_PICK_RADIUS` — правила отрубания.
* `zombie.gd → WALK_SPEED / CRAWL_SPEED / ATTACK_RANGE`.

## Ограничения (честно)

* Модели из репозитория — статичные меши **без готовых анимаций и рига**.
  Скелет подобран автоматически по геометрии, анимации процедурные (синусоиды и
  наборы поз), а не захваченные с живого актёра. Бег, удар мечом, ползание и
  смерть читаются, но это не AAA-анимация.
* Текстуры персонажей — исходные AI-ассеты 4096², они «грязные» с самого начала
  (пятна на коже). Уменьшены до 2048² для веса.
* Атлас острова — 4096² на ~20 км, то есть ~5 м на тексель: у арены один
  тексель покрывает несколько метров, и «как на модели» текстура там не
  читается физически. Игра рисует землю родным атласом и добивает масштаб
  двумя плитками, собранными из **того же** атласа (`tools/make_ground_mottle.py`
  — бежевые разводы, повтор ~320 м; `tools/make_ground_detail.py` — зерно,
  повтор ~9 м), см. `game/shaders/ground.gdshader`. Чужой плитки нет.
* Дальний план (океан + горизонт) на llvmpipe выглядит выбеленным: небо у
  горизонта светлое, а скриншоты сняты без HDR/сглаживания. На обычной видеокарте
  контраст выше.
* Земля в игре — не `island.glb`, а заново собранный терраин
  (`game/models/island_terrain.glb`, см. ниже): готовый меш после децимации
  давал дыры и «просвечивающие» плоскости.

## Земля: карты высот вместо децимированного меша

`game/models/island.glb` — исходный остров, ужатый децимацией до 500k
треугольников (ради размера). У арены от этого остались плоскости размером в
километр и дыры, поэтому земля рисуется заново:

```
python3 tools/make_terrain.py        # → game/models/island_terrain.glb + heightmap.f32
```

* высоты берутся из **исходного** меша (`остров/2 остров улучшенный.zip`;
  скрипт сам склеивает `.z01/.z02/.zip` и распаковывает единственный glb);
* площадка арены (220×220 м) — сетка 1 м; эта же карта пишется в
  `heightmap.f32`, по ней строится `HeightMapShape3D`, так что игрок ходит
  ровно по нарисованному;
* остальной остров — сетка 24 м по верхней огибающей, плавно стыкуется с
  площадкой (96 м перехода);
* нормали считаются по полю высот, UV — та же аффинная развёртка, что у
  модели, поэтому цвета атласа совпадают;
* исходный меш терраина (`node_0`) в игре скрыт, растительность и островки
  остаются.

## Проверка в движке

Проект прогоняется в реальном Godot через GitHub Actions
(`.github/workflows/godot-check.yml`): импорт, `--check-only` по всем скриптам,
`tests/check.gd` (86 проверок) и кадры из живой сцены (`tests/shots.gd`,
xvfb + llvmpipe, 800×450). Результат — `ci/report.md` и `ci/shots/*.png`,
кадры в `game/preview/engine_*.png`.

```
godot --headless --path game --import
godot --headless --path game --quit-after 30000 --script res://tests/check.gd
SHOT_DIR=/tmp/shots xvfb-run -a godot --path game --resolution 800x450 \
    --rendering-driver opengl3 --script res://tests/shots.gd
```

На момент последней проверки: Godot 4.3.stable, **86 проверок, 0 провалов**,
импорт с единственным безобидным предупреждением про LOD.
